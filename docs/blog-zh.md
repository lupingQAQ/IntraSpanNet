# 六个公开流量基准的 train/test 重叠约 80%

我们对用于对比的公开流量分类基准做了一次重复审计。六个基准中有五个的 train 与 test 存在大量字节级完全相同的流，重叠约占 test 的 80%。Tor 是例外，重叠为 0%。

这篇文章说明审计方法、在去重协议下训练的模型，以及两者的边界。

## 为什么审计 split

公开基准上的流量分类准确率经常在 0.99 以上。这些数字难以横向比较，因为预处理、split 构造和包预算都不同。有一个变量很少被讨论：同一条流是否同时出现在 train 与 test。

我们对分发的 train、validation、test 目录逐文件计算哈希。两种口径：PNG 文件字节的 MD5，以及解码后灰度像素的 MD5。两种口径结果一致。重复是字节级全同，不是近重复。

| 基准 | Train | Test | Train ∩ test | 占 test | 去重后 test |
|---|---:|---:|---:|---:|---:|
| ISCXVPN2016 | 13,281 | 1,384 | 1,106 | 79.9% | 278 |
| ISCXTor2016 | 11,655 | 1,458 | 0 | 0% | 1,458 |
| USTC-TFC2016 | 37,323 | 6,662 | 5,605 | 84.1% | 1,057 |
| CICIoT2022 | 18,734 | 1,951 | 1,571 | 80.5% | 380 |
| CrossPlatform-Android | 44,700 | 4,656 | 3,733 | 80.2% | 923 |
| CrossPlatform-iOS | 40,379 | 4,205 | 3,396 | 80.8% | 809 |

跨 split 的标签冲突为 0。所有重复都在同一类内。

更可能的原因是各 split 从同一流池独立采样，没有做跨 split 去重。这是数据分发本身的属性，不是某一篇论文引入的。所有在同一批文件上评测的方法，都受到同样影响。

## 影响

这些基准上的绝对准确率被抬高。test 中约 80% 的样本是记忆题。模型可以靠记住流身份取得高分，而不是学到协议行为。

同 split 对比仍然成立，因为重叠对双方影响相同。但这些数字不能作为跨网络泛化的证据。

Tor 是集合中唯一干净的基准。报告中对 Tor 的对比是最有力的证据。其余五个基准同时报告原始 split 与去重后的 test 子集。去重后，本方 macro-F1 下降 1.4 至 4.4 个百分点；相对外部基线的领先没有缩小。

## 模型

模型使用四个 Gated DeltaNet block，单臂 2.86M 参数。输入为一条单向流的前 5 个包，每包 320 字节，共 1600 字节。每包包含 80 字节 IPv4 与传输层头、240 字节载荷。IPv4 源地址与目的地址置零。

模型有四个头：产品 18 类、类型 10 类、大类 3 类、恶意家族 11 类。产品头是闭集。开放集由原型距离判定：每类 3 个子原型，推理时取 1 减去与任一原型的最大余弦相似度。两个门控臂的平均距离超过 0.1041 时，输出未知。

发布系统对四个分类臂与两个门控臂取平均。各臂结构相同，差异在预训练配方、损失权重与硬负样本采样。

训练分三步：33,184 条纯训练流上的对比预训练；60 轮多任务 SFT；300 轮带奖励塑形的 REINFORCE 微调。

验证集按流级拆成 dev 与 test 两半。阈值校准、checkpoint 选择与集成选择只用 dev。test 只用于最终报告。

## 结果

| 指标 | test（503 流） | 全验证集（1006 流） |
|---|---:|---:|
| 产品准确率 | 0.8787 | 0.8817 |
| 大类准确率 | 0.9245 | 0.9334 |
| Macro-F1（有支撑类） | 0.7621 | 0.8240 |
| 门控 AUROC | 0.9784 | 0.9820（dev） |

验收集中 18 个未知产品 bins 全部拒识。操作点在 q=0.64 至 0.75 区间稳定。

验收 demo 共 264 个产品 bins。原始集成接受 10 个产品中的 8 个。加上内部时序救援规则后为 9 个。时序规则未包含在发布版本中，因此发布模型复现的是 8/10。

`stunnel` 是唯一零召回的产品（0/30），需要注册或补充数据。test 为流级拆分，不是会话级；每类只有 1 个留出会话。这些限制比准确率小数点后的第三位更重要。

## 发布内容

- 四臂 V5 集成与原型矩阵。
- 便携推理包，含 pcap/pcapng 预处理。
- CLI 与 1620 字节 FLW1 记录的 HTTP 服务。
- 评测脚本与 split 审计脚本。
- 模型卡、结果说明与基准审计。

不支持 CPU 推理。GDN 骨干使用 Triton 内核，必须使用 CUDA。参考显卡为 RTX 4090；集成在 batch 128 时峰值显存约 3.4GB，吞吐约 253 flows/s。

代码与权重使用 Apache-2.0，文档使用 CC-BY-4.0。仓库不包含抓包。

## 复现审计

审计脚本为 `scripts/audit_split_dups.py` 与 `scripts/audit_split_labels.py`。输入为按类分目录的基准文件，输出字节重叠、像素重叠、每类计数与标签冲突。干净子集清单在本地生成，不随仓库分发，因为基准文件名包含采集元数据。

如果你维护公开流量数据集，最有价值的下一步是在发布前做跨 split 去重。如果你报告基准数字，请说明 split 是否含重复。这比再多一位小数更有用。
